## 0. 핵심 개발 지시

당신은 React, TypeScript, CSS, Supabase 및 Cloudflare Pages 기반 서비스 개발을 담당하는 시니어 풀스택 엔지니어다.

기존 모카 팬 편지 프로젝트를 참고하여 아리사를 위한 독립 편지 서비스를 개발하라.

**이번 프로젝트에서 가장 중요한 요구사항은 다음과 같다.**

1. 기존 모카의 편지 작성 화면 구조를 그대로 따른다.
2. 기존 모카의 편지봉투 개봉·편지지 등장 애니메이션과 열람 UX를 그대로 재사용한다.
3. 관리자 검수, 읽음 처리, 접근 코드 등 기존 기능도 유지한다.
4. 디자인은 모카의 블루·라벤더 색감 대신 핑크 중심으로 변경한다.
5. 배경 이모지는 `Enchanted Pink → Disenchanted`라는 독립적인 연출을 적용한다.
6. 기존 모카 서비스의 CSS, DB, 데이터 및 배포에 영향을 주지 않는다.

새 디자인을 만든다는 이유로 기존에 완성된 편지 기능을 처음부터 다시 개발하지 말 것.

## 1. 프로젝트 및 데이터베이스 구성


기존 모카 프로젝트와 같은 상위 경로에 생성한다.

기존 프로젝트는 읽기 전용으로 참조한다.

기술 스택은 기존 모카 구현을 우선 확인한 뒤 React, Vite, TypeScript, Tailwind CSS, Supabase, Cloudflare Pages를 기본으로 한다.

Supabase는 기존 `mokano.live` 서비스와 동일한 프로젝트를 사용한다.

아리사 전용 테이블:
- `arisa_last_live_letters`
- `arisa_letter_submission_limits` 등 필요한 부속 테이블

기존 모카 테이블을 수정하거나 다른 용도로 사용하지 않는다.

아리사의 접근 코드, 세션, 관리자 화면, 클라이언트 캐시 및 제출 제한을 별도 네임스페이스로 격리한다.

  165deg,

배경 위에 다음 요소를 별도 레이어로 적용한다.

- 중앙의 부드러운 크림색 조명

배경의 색상 변화는 매우 느리고 자연스러워야 한다.

무지개색, 보라색 중심 배경, 강한 네온핑크는 사용하지 않는다.

기존 모카의 다음 레이아웃 특성은 그대로 유지한다.

- 중앙 정렬
- 적절한 최대 너비
- 둥근 모서리
- 반투명 카드
- 부드러운 그림자
- 편지지 형태의 입력창
- 모바일 단일 열 구성

단, 기존 보라색 그림자는 로즈색으로 변경한다.

주요 버튼은 다음 계열로 제작한다.

`#AD3E6C → #C9638C`

버튼 문자는 흰색이며 접근성 대비를 확인한다.

입력창과 편지지에는 지나치게 많은 핑크를 입히지 않는다. 실제로 글씨가 적히는 종이는 따뜻한 아이보리색으로 남겨둔다.

## 4. 배경 컨셉: Enchanted Pink → Disenchanted

### 디자인 개념

이 프로젝트의 핵심 시각적 주제는 다음과 같다.

**"핑크빛으로 반짝이던 마법이 마지막 무대와 함께 서서히 풀려가지만, 팬들이 남긴 편지는 계속 남아 있다."**

밝고 사랑스러운 핑크가 점점 희미해지는 감정적 연출이다.

공포, 어둠, 파괴, 화려한 폭발과 같은 연출은 사용하지 않는다.

전체 배경은 끝까지 핑크빛을 유지한다.

마법이 풀리는 모습은 배경에 떠 있는 작은 이모지와 빛의 변화로 표현한다.

### 사용할 이모지

1차 그룹 — Enchanted Pink
- 💖
- 💗
- 💞
- 🩷
- 💕
- 🎀
- 🌸
- ✨

2차 그룹 — Disenchantment
- 🫧
- 🥀
- 🥹
- 💔
- ✧
- 작은 빛 입자

전체적으로 사랑스럽고 몽환적인 이미지를 우선한다.

눈물과 이별 계열 이모지는 전체의 약 20~30% 이하로 제한한다.

실제로 색상을 세밀하게 제어해야 하는 작은 입자는 이모지 대신 CSS 도형 또는 가벼운 SVG를 사용해도 된다.

### 이모지 생명주기

각 이모지는 다음 다섯 단계를 반복한다.

**Step 1 — Enchant**

이모지가 천천히 등장한다.

- 불투명도 증가
- 작은 핑크빛 후광
- 미세한 확대
- 부드러운 흔들림

**Step 2 — Shimmer**

완전히 나타난 이모지는 잠시 빛난다.

- 약한 밝기 변화
- 좌우로 흔들림
- 미세한 회전
- 주변 작은 별 입자 반짝임

**Step 3 — Disenchant**

이모지의 마법이 서서히 풀린다.

- 후광이 감소한다.
- 채도가 약해진다.
- 밝기가 원래 상태로 돌아온다.
- 크기가 조금 줄어든다.

**Step 4 — Dissolve**

이모지가 사라진다.

- 투명도가 천천히 0에 가까워진다.
- 주변 작은 입자가 흩어진다.
- 일부는 아래로 내려가고 일부는 위로 떠오른다.

**Step 5 — Reappear**

서로 다른 위치와 지연시간으로 새로운 이모지가 등장한다.

화면 전체가 한 번에 사라지거나 동시에 나타나는 일은 없어야 한다.

### 중요: 이모지 색상 처리

운영체제별 컬러 이모지는 렌더링 방식이 다르므로 CSS의 color 속성만으로 핑크색을 일관되게 변경할 수 없다.

따라서 다음과 같이 구현한다.

- 이모지 본체는 기본 컬러를 사용한다.
- 핑크 후광은 별도 CSS 레이어로 구현한다.
- Disenchant 단계에서 opacity, filter, scale을 변화시킨다.
- 정말 정확한 색상 변화가 필요한 입자는 CSS/SVG 도형으로 만든다.
- 기기별 렌더링 차이로 깨지는 효과는 사용하지 않는다.

## 5. CSS 애니메이션 구현 원칙

아래 CSS는 신규 연출의 참고 구현이다.

실제 프로젝트의 DOM과 기존 애니메이션 클래스를 확인하고 그 구조에 맞게 적용하라.

```css
@keyframes arisaDisenchant {
  0% {
    opacity: 0;
    filter: saturate(1.2) brightness(1.08);
    transform: scale(0.85);
  }

  16% {
    opacity: 0.88;
    filter: saturate(1.2) brightness(1.12);
    transform: scale(1.05);
  }

  42% {
    opacity: 0.9;
    filter: saturate(1.05);
    transform: scale(1);
  }

  72% {
    opacity: 0.48;
    filter: saturate(0.55) brightness(1);
    transform: scale(0.94);
  }

  100% {
    opacity: 0;
    filter: saturate(0);
    transform: scale(0.8);
  }
}
```

### 애니메이션 계층 분리

기존 모카의 fall / sway / rise / glow 동작을 재사용하되, 새 Disenchant 애니메이션과 transform 충돌이 발생하지 않도록 한다.

가능하면 두 계층을 사용한다.

- 외부 요소: 위치 이동, fall, sway, rise
- 내부 요소: shimmer, glow, disenchant, opacity, scale

기존 봉투 개봉 애니메이션의 keyframes는 수정하지 않는다.

배경 이모지에만 새로운 keyframes를 적용한다.

### 권장 설정

- 모바일 이모지: 최대 10~14개
- 데스크톱 이모지: 최대 18~24개
- 생명주기: 약 12~22초
- 위치: 화면 양쪽 가장자리 중심
- 이동: 느리고 작은 움직임
- 랜덤 시드: 렌더링 간 안정적인 값
- 폼 위를 가리는 장식 금지

배경 이모지는 아래 속성을 갖도록 한다.

```css
pointer-events: none;
user-select: none;
```

접근성 트리에서도 장식 요소를 제외한다.

`prefers-reduced-motion`을 지원하고, 사용자가 애니메이션을 끌 수 있도록 한다.

비활성 브라우저 탭에서는 가능한 범위에서 애니메이션을 정지한다.

매 프레임 React state를 갱신하지 않는다.

## 6. 기존 편지 애니메이션 — 변경 금지

기존 모카 프로젝트의 편지 애니메이션은 그대로 사용한다.

아리사의 배경 효과를 도입하면서 다음 동작이 변경되어서는 안 된다.

### 편지 작성

- 편지지 모양
- 종이의 가로줄
- 입력 영역 크기
- 문장 및 줄바꿈 처리
- 버튼 배치
- 제출 성공 연출
- 편지 작성 안내 문구의 위치

문구는 모카에서 아리사로만 변경한다.

### 편지 열람

다음 순서를 유지한다.

1. 봉투 선택
2. 선택 강조
3. 하트 봉인 사라짐
4. 봉투의 삼각 플랩 열림
5. 편지지가 위로 올라옴
6. 편지 원문 열람 화면 표시

기존 약 1.2~1.6초의 개봉 애니메이션 길이를 우선 유지한다.

봉투의 형태, 크기, 회전축, transform-origin, 타이밍 함수 및 전환 순서를 임의로 변경하지 않는다.

봉투 본체의 색상만 라벤더에서 핑크로 변경할 수 있다.

편지지는 아이보리색을 사용하고 하트 봉인은 로즈핑크로 변경한다.

긴 편지의 스크롤, 이전/다음 편지 버튼, 목록 복귀, 키보드 접근성과 연출 건너뛰기도 기존 방식 그대로 유지한다.

### 배경 이모지와 편지 개봉의 관계

봉투가 열리는 순간에도 전체 애니메이션 구조는 유지한다.

단, 긴 편지를 읽는 화면에서는 배경 이모지의 불투명도를 낮춰 본문 가독성을 확보한다.

편지 개봉 순간에 새로운 대형 폭발 이펙트나 화면 전환 효과를 추가하지 않는다.

- 기존 봉투 개봉 애니메이션
- 읽음/안 읽음 분류
- 전체 편지 개수
- 편지 상세 열람
- 읽음 기록 저장

기존 모카와 동일한 데스크톱 2열 및 모바일 편지함 UX를 적용한다.

읽음 기록은 아리사 본인 모드에서 원문을 실제로 열람한 이후에만 최초 1회 기록한다.

### 관리자 — `/admin`

기존 Supabase Auth 계정 중 명시적으로 허용된 관리자 UID만 접근할 수 있다.

- 관리자 로그인
- 대기 편지 조회
- 승인
- 숨김
- 승인 취소
- 통계
- 편지 미리보기

관리자 미리보기는 아리사의 읽음 기록을 변경하지 않는다.

관리자 인증과 아리사 접근 코드 인증은 서버에서 완전히 구분한다.

### 현장 안내 — `/display`

태블릿 전체화면을 지원한다.

- `ARISA · LAST LIVE`
- `아리사에게 편지를 남겨주세요`
- 편지 작성 페이지 QR 코드
- 작은 전체화면 버튼
- 동일한 Enchanted Pink → Disenchanted 배경

QR 코드는 실제 아리사 서비스 주소를 가리켜야 한다.

기존 모카 QR 코드를 재사용하지 않는다.

## 8. 서버 및 Supabase 보안

- 아리사 전용 편지 테이블에 RLS를 적용한다.
- 팬이 다른 편지를 조회할 수 없도록 한다.
- 팬의 원문은 일반 텍스트로 저장하고 안전하게 출력한다.
- 편지 제출과 48시간 제한을 원자적으로 처리한다.
- 요청 재시도로 편지가 중복 저장되지 않도록 한다.
- Service Role Key는 서버에서만 사용한다.
- 관리자 권한과 아리사 세션은 모든 보호 API에서 서버 검증한다.
- 미승인 편지 및 숨긴 편지는 아리사에게 전송하지 않는다.
- 편지 원문과 인증 관련 응답은 공용 캐시에 저장하지 않는다.
- 기존 모카 테이블, 정책, Auth 사용자 및 데이터는 변경하지 않는다.

기존 프로젝트에서 검증된 인증·보안 코드를 확인하고 적절하게 재사용한다.

## 9. 모바일 및 성능 최적화

화면 크기별로 검증한다.

- 360px 모바일
- 일반 스마트폰
- 태블릿 세로
- 태블릿 가로
- 데스크톱

모바일에서도 배경이 충분히 핑크빛으로 보이게 한다.

과도한 blur와 GPU 부하는 피한다.

배경 장식 때문에 편지 작성 시 키보드 입력이 느려지거나 스크롤이 흔들려서는 안 된다.

애니메이션을 끈 상태에서도 아름다운 정적인 핑크 배경과 편지 UI가 유지되어야 한다.
